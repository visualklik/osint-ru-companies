# osint-ru-companies

Корпоративная разведка по российским юридическим лицам на бесплатных
официальных источниках. Работает как навык Claude Code и как набор
самостоятельных CLI-скриптов.

Отвечает на три вопроса, которые обычно и задают: **кто владеет компанией**,
**сколько она зарабатывает** и **с кем связана**. Всё найденное копится в
локальной SQLite, поэтому пересечения между разными проверками находятся сами
собой — чем больше компаний загружено, тем больше связей всплывает.

Только стандартная библиотека Python. Ни одного API-ключа. Ни одной платной
подписки.

---

## Что умеет

| Задача | Источник | Модуль |
|---|---|---|
| Руководитель, учредители с ИНН и долями, адрес, ОКВЭД, лицензии, филиалы, статус | ЕГРЮЛ, `egrul.nalog.ru` | `egrul.py` |
| Выручка, прибыль, активы, капитал, долги — формы 1–4 за 5 лет | ГИР БО, `bo.nalog.gov.ru` | `girbo.py` |
| Численность работников, налоговая задолженность, доходы/расходы, спецрежимы | массовые выгрузки ФНС | `opendata.py` |
| Фактический адрес работы и перечень должностей | реестр деклараций СОУТ, Роструд | `rostrud.py` |
| Проверки, предостережения, профилактические визиты | ЕРКНМ, Генпрокуратура | `erknm.py` |
| Арбитражные дела, роли сторон, частые оппоненты | `kad.arbitr.ru` | `kad.py` |
| Обратный поиск «человек → его компании» | rusprofile, list-org | `people.py` |
| Граф владения и контроля, накопление, пересечения | локальный SQLite | `crawl.py` |
| Досье, граф в DOT/Mermaid, карточка человека | | `report.py` |

### Чем это отличается от «пробить ИНН на сайте»

Три вещи, которых нет у бесплатных агрегаторов:

**Фактический адрес вместо юридического.** Реестр деклараций СОУТ публикует, где
организация работает на самом деле. В реальном деле это вскрыло четыре компании
в одном офисе, две из которых числились по совсем другим адресам.

**Структура персонала.** Перечень должностей показывает, держит ли управляющая
компания свою службу эксплуатации или отдала работы подрядчику. Компания с
двадцатью рабочими и компания с одним юристом и расчётным отделом — это разные
бизнес-модели, и в отчётности они выглядят одинаково.

**Накопительная база.** `crawl.py links` ищет пересечения по всему, что
загружено: общие физлица, общие юридические и фактические адреса, цепочки
владения, совместные арбитражные дела.

## Установка

```bash
git clone https://github.com/visualklik/osint-ru-companies.git
cd osint-ru-companies
sudo apt install poppler-utils        # нужен pdftotext для разбора выписок ЕГРЮЛ
```

Python 3.9+ из коробки, зависимостей нет. Опционально `graphviz` — для
отрисовки графа в SVG; без него есть вывод в Mermaid.

Как навык Claude Code:

```bash
ln -s "$(pwd)" ~/.claude/skills/osint-ru-companies
```

База по умолчанию — `data/corp.db`, путь меняется через `--db` или переменную
`RU_CORP_DB`.

## Быстрый старт

```bash
cd scripts

# 1. Найти ИНН по названию (заодно покажет текущего руководителя)
python3 egrul.py "название компании" --search-only

# 2. Загрузить компанию и её владельцев, пройдя два хопа вверх по цепочке
python3 crawl.py add 7721546864 --depth 2 --case моё_дело

# 3. Досье
python3 report.py dossier 7721546864

# 4. Пересечения по всей базе
python3 crawl.py links --case моё_дело

# 5. Граф
python3 report.py graph --case моё_дело --format mermaid
```

Дальше по вкусу:

```bash
python3 opendata.py load sshr2019          # численность, ~94 МБ, минута
python3 rostrud.py load --case моё_дело    # фактические адреса и должности
python3 rostrud.py addresses               # кто сидит в одном офисе
python3 rostrud.py profile                 # у кого свой персонал, у кого нет
python3 erknm.py load --year 2026 --case моё_дело   # проверки
python3 people.py person "ФАМИЛИЯ ИМЯ ОТЧЕСТВО" --inn 111111111111
```

## Модули

### `egrul.py` — ЕГРЮЛ

Официальный реестр ФНС. Два уровня детализации:

```bash
python3 egrul.py 7721546864 --search-only      # дёшево: название, ОГРН, регион, руководитель
python3 egrul.py 7721546864                    # полная выписка: учредители с ИНН и долями
python3 egrul.py 7721546864 --keep-pdf ./pdfs  # сохранить исходный PDF
```

Выписка приходит в PDF, парсер разбирает её в структуру: руководитель,
учредители-физлица с ИНН и долями, учредители-юрлица, управляющая организация,
уставный капитал, все ОКВЭД, лицензии, филиалы, статус.

Парсер устроен вокруг того, что выписка — это таблица с тремя колонками, где и
подпись, и значение переносятся на следующие строки. Различить перенос от нового
поля можно только по колонке, в которой начинается текст, поэтому разбор ведётся
по позициям символов, а не по регулярным выражениям на строку. История записей
ЕГРЮЛ отсекается, иначе она затирает текущее состояние.

Темп: 1,5 с между шагами, меняется переменной `EGRUL_PAUSE`. При слишком частых
запросах сервис включает капчу — скрипт говорит об этом явно.

### `girbo.py` — бухгалтерская отчётность

```bash
python3 girbo.py 7721546864            # сводка + красные флаги
python3 girbo.py 7721546864 --full     # все строки форм 1–4
```

Формы 1–4 за пять лет. Считает маржу, ROE, долю капитала, динамику выручки год
к году и подсвечивает: отрицательный капитал, чистый убыток, обвал выручки
более чем на половину, оборот больше активов в 50 раз, нулевую выручку при
поданной отчётности.

**Единицы.** ГИР БО отдаёт значения в тысячах рублей. Модуль переводит их в
рубли на входе (`girbo.UNIT`), чтобы цифры можно было сравнивать с суммами
контрактов и уставным капиталом.

Банки и страховщики сюда не отчитываются — они сдают в ЦБ. Пустой ответ по
такой компании корректен.

### `opendata.py` — массовые выгрузки ФНС

```bash
python3 opendata.py load sshr2019      # численность работников
python3 opendata.py load --all         # все наборы, ~330 МБ
python3 opendata.py show 2309085638
python3 opendata.py status
```

Наборы: `sshr2019` среднесписочная численность, `debtam` недоимка, пени и
штрафы, `revexp` доходы и расходы, `snr` спецрежимы. Качаются один раз целиком
на всю страну, дальше работают офлайн без лимитов.

Покрытие численности — около 2,04 млн юрлиц при более чем 3 млн действующих;
организации под санкциями из публикации исключены. Дата одна, последняя
опубликованная. Численность относится к юрлицу, а не к группе: у холдинговой
компании это несколько десятков человек, тогда как в группе их десятки тысяч.

### `rostrud.py` — фактический адрес и штат

```bash
python3 rostrud.py load --case моё_дело
python3 rostrud.py show 7721546864
python3 rostrud.py addresses     # общие фактические адреса и расхождения с ЕГРЮЛ
python3 rostrud.py profile       # свой персонал против «только офис»
```

Самый недооценённый источник в наборе. Декларации специальной оценки условий
труда публикуют **фактический адрес осуществления деятельности** и **перечень
должностей** с численностью по каждому рабочему месту. ФИО не публикуются.

Сопоставление адресов идёт по ключу «улица + дом»: индекс, регион, город и номер
помещения отбрасываются, потому что один и тот же дом в реестрах пишут десятком
способов, вплоть до опечаток в индексе. Соседние дома при этом не склеиваются.

### `erknm.py` — проверки

```bash
python3 erknm.py available
python3 erknm.py load --year 2026 --case моё_дело
python3 erknm.py show 7721546864
```

Единый реестр контрольных мероприятий Генпрокуратуры: проверки, предостережения,
профилактические визиты. Для управляющих компаний ЖКХ это самый показательный
публичный след — реестры ФНС говорят, кто владеет компанией, а этот говорит,
как она себя ведёт.

Поиск на сайте защищён капчей, поэтому модуль работает через официальный экспорт
открытых данных — тот же реестр, машиночитаемый канал, опубликованный
оператором именно для автоматической обработки. Выгрузки помесячные, около
300 МБ каждая, доступны с 2021 года; полная история — порядка 20 ГБ, так что
грузите нужные годы. Сервер рвёт соединение на больших файлах, загрузка
докачивается с места обрыва.

Флаг `--erp` переключает на старый Единый реестр проверок (294-ФЗ).

### `kad.py` — арбитраж

```bash
python3 kad.py fetch 7721546864 --pages 4
python3 kad.py show 7721546864
```

Совместные дела и общие контрагенты в процессах — самый сильный признак
хозяйственной связи, которого нет ни в одном реестре. Дела складываются в базу
вместе со всеми сторонами, дальше `crawl.py links` показывает пересечения.

**Сервис банит адреса по частоте запросов** и отдаёт HTTP 451 с HTML-страницей
вместо JSON. Под бан попадают адреса дата-центров, VPN и общих выходных узлов
целиком, и реальный браузер оттуда блокируется так же, как скрипт. Модуль
распознаёт это состояние и сообщает о блокировке явно, а не выдаёт её за «дел
нет». Запускать нужно с обычного домашнего или офисного подключения.

### `people.py` — обратный поиск

```bash
python3 people.py person "ФАМИЛИЯ ИМЯ ОТЧЕСТВО" --inn 111111111111
python3 people.py shared
```

В реестрах ФНС обратного индекса нет: поиск по ФИО на `egrul.nalog.ru` находит
только ИП, поиск по личному ИНН не даёт ничего. Индекс берётся у агрегаторов.

**rusprofile — основной.** Страница человека адресуется напрямую по шаблону
`/person/<фамилия-транслитом>-<инициалы>-<ИНН>`, поиска нет, а значит и упираться
в лимит нечему. Отдаёт компании с ИНН, выручкой и адресом, и — что особенно
ценно — историю выходов из состава с датами.

**list-org — запасной** (`--source list-org`). Богаче по деталям: доли,
телефоны, статус. Но ограничивает частоту примерно после десяти запросов, а
затем блокирует адрес совсем.

`--inn` обязателен: оба источника ключуют людей по личному ИНН, а без него
однофамильцев набираются десятки.

**Данные агрегаторов отстают от реестра** на месяцы и годы. Это лид, а не
истина: каждую компанию сверяйте через `crawl.py add`. Расхождение само по себе
ценно — оно показывает, что человек вышел из состава, и когда.

### `crawl.py` — обход и пересечения

```bash
python3 crawl.py add 7721546864 --depth 2 --case моё_дело
python3 crawl.py expand --limit 30      # добрать очередь после --limit
python3 crawl.py links --case моё_дело
python3 crawl.py status
```

Обход идёт вверх по корпоративной цепочке: юрлица-учредители и управляющие
организации ставятся в очередь автоматически. Очередь переживает перезапуск.

`links` показывает пять видов пересечений: общие физлица, общий юридический
адрес, общий фактический адрес по декларациям СОУТ, цепочки корпоративного
владения, совместные арбитражные дела.

### `report.py` — отчёты

```bash
python3 report.py dossier 7721546864 --out dossier.md
python3 report.py graph --case моё_дело --format mermaid --out graph.mmd
python3 report.py person "Фамилия"
```

Досье собирает всё, что есть в базе по одной компании: реквизиты, руководство,
владельцев, финансы за пять лет с красными флагами, численность и выручку на
сотрудника, налоговую задолженность, рабочие места и фактические адреса,
проверки, арбитраж, лицензии, виды деятельности и связи по накопленной базе.

## Методика

Порядок, который себя оправдал:

1. Начать с ИНН. Нет ИНН — найти поиском по названию, сверить регион и
   руководителя, чтобы не взять однофамильца-двойника.
2. Загрузить с `--depth 2`. Больше двух хопов почти всегда даёт шум.
3. Прочитать досье. Смотреть на несоответствие масштаба выручки уставному
   капиталу, отрицательный капитал, смену директора незадолго до сделки, статус
   реорганизации или ликвидации.
4. Догрузить Роструд и прогнать `addresses`. Фактический адрес — то место, где
   формально независимые компании чаще всего сходятся.
5. Прогнать `profile`. Управляющая или подрядная компания без собственного
   рабочего персонала означает, что работы выполняет кто-то ещё.
6. Прогнать `links`. Общий директор, общий адрес или совместное дело между
   формально независимыми компаниями — самые твёрдые признаки связи.
7. Обратный поиск по каждому фигуранту. Найденные компании догрузить и повторить
   `links` — с каждой новой компанией база находит больше пересечений.

### Проверяйте совпадения контрольной выборкой

Самая частая ошибка в такой работе — принять административный артефакт за
признак связи. Два примера из реального дела, оба выглядели убедительно и оба
оказались пустыми:

- **Синхронные записи в ЕГРЮЛ.** У всех четырёх целей стояли записи от одних и
  тех же дат. Проверка пяти несвязанных компаний того же города показала те же
  даты — это массовые технические обновления реестра силами ФНС.
- **Предостережения надзорного органа в один день.** Пять компаний получили их
  одновременно, с почти подряд идущими номерами. В тот же день их получили ещё
  69 организаций: массовая кампания жилинспекции.

Правило простое: нашли совпадение — возьмите три-пять заведомо несвязанных
компаний того же профиля и региона и проверьте, есть ли оно у них. Если есть —
это фон, а не сигнал.

## Чего скил не умеет

- **Состав акционеров АО и ПАО в ЕГРЮЛ не раскрывается** — там пусто по закону,
  а не из-за ошибки парсера. Смотреть раскрытие эмитента и реестродержателя.
- **Банки и страховщики не сдают отчётность в ГИР БО.**
- **Поимённого состава сотрудников подключённые источники не содержат.** ЕГРЮЛ
  даёт должностных лиц, ГИР БО — цифры, выгрузки ФНС — агрегаты, Роструд —
  должности без ФИО.
- **Численность ФНС — одна дата и не для всех.** Около 2 млн юрлиц, компании под
  санкциями исключены.
- **Госзакупки, ФССП, Федресурс и ГИС ЖКХ не подключены.** Что там есть и чем
  берётся — в [references/sources.md](references/sources.md).

### Блокировки по IP

Несколько источников блокируют адреса дата-центров и VPN целиком:
`kad.arbitr.ru` (451), `ras.arbitr.ru`, `fedresurs.ru` (403), `list-org.com`
(таймаут), `zachestnyibiznes.ru` (403). Реальный браузер с такого адреса
блокируется наравне со скриптом. Официальные источники — ФНС, Генпрокуратура,
Роструд — таких ограничений не имеют и работают откуда угодно.

## Правовая рамка

ЕГРЮЛ, ГИР БО, открытые данные ФНС, реестр контрольных мероприятий, реестр
деклараций СОУТ и картотека арбитражных дел — официально открытые данные.
Руководители, учредители и бенефициары публикуются в ЕГРЮЛ в силу закона.

ФИО сотрудников допустимо собирать из источников, где человек назван в
профессиональном качестве и публикация исходит от самой организации или от
государственного органа: контактные лица в закупочной документации,
представители сторон в судебных материалах, разделы «команда» на сайте
компании, отраслевые реестры.

За рамками инструмента: домашние адреса, личные телефоны, семья, частные
аккаунты и любое сведение данных о конкретном человеке в профиль, не связанный
с его рабочей ролью.

Условия использования открытых данных требуют сохранять ссылку на источник.
При публикации результатов указывайте: ФНС России, ФГИС ЕРКНМ Генеральной
прокуратуры РФ, Роструд.
