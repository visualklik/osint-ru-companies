# Источники по российским юрлицам

Статус проверен вживую 10.08.2026. Отмечено, что подключено к скилу, а что нет.

## Подключено

### ЕГРЮЛ — egrul.nalog.ru
Официальный реестр ФНС. Бесплатно, без ключа, без капчи при разумном темпе.

Цепочка запросов (реализована в `scripts/egrul.py`):

1. `POST /` с полями `query`, `region`, `vyp3CaptchaToken`, `page`,
   `PreventChromeAutocomplete` → `{"t": <токен поиска>, "captchaRequired": false}`
2. `GET /search-result/<токен>` → `{"rows": [...]}`. В строке: `i` ИНН, `o` ОГРН,
   `c` краткое наименование, `n` полное, `p` КПП, `rn` регион, `r` дата
   регистрации, `g` текущий руководитель строкой, `k` тип (`ul` юрлицо, `fl` ИП),
   `t` токен строки для выписки.
3. `GET /vyp-request/<токен строки>` → токен выписки
4. `GET /vyp-status/<токен выписки>` → `{"status": "ready"}`
5. `GET /vyp-download/<токен выписки>` → PDF

Выписка содержит: полное и краткое наименование, адрес, способ образования,
дату регистрации, регистрирующий орган, руководителя (ФИО, ИНН, должность),
учредителей — физлиц с ИНН и долями и юрлиц с ОГРН, ИНН и долями, управляющую
организацию, уставный капитал, все ОКВЭД, лицензии, филиалы и
представительства, регистрацию в СФР, а также полную историю записей ЕГРЮЛ
(парсер её отсекает, чтобы не дублировать текущее состояние).

Поиск по ФИО возвращает только ИП. Директорских позиций по человеку тут нет.

### ГИР БО — bo.nalog.gov.ru
Бухгалтерская отчётность с 2019 года. Бесплатно, без ключа, JSON.

- `GET /advanced-search/organizations/search?query=<ИНН>&page=0` → `content[0].id`
  плюс реквизиты, ОКВЭД, ОКОПФ, ОКФС, статус
- `GET /nbo/organizations/<id>/bfo/` → массив периодов; в каждом
  `typeCorrections[0].correction` лежат `balance` (форма 1), `financialResult`
  (форма 2), `capitalChange` (форма 3), `fundsMovement` (форма 4)

Значения — по кодам строк с префиксом `current` / `previous`, например
`current2110` это выручка отчётного периода. Ключевые коды: 2110 выручка,
2120 себестоимость, 2200 прибыль от продаж, 2400 чистая прибыль, 1600 активы,
1300 капитал, 1500 краткосрочные обязательства, 1230 дебиторка, 1520 кредиторка.

Хост важен: JSON отдаёт только `bo.nalog.gov.ru`, а `bo.nalog.ru` возвращает
HTML-обёртку SPA.

Банки и страховщики не сдают сюда — отчитываются в ЦБ. Отсутствие ответа по
такой компании нормально.

### Картотека арбитражных дел — kad.arbitr.ru
Реализовано в `scripts/kad.py`. Кто с кем судится, роли, категории дел,
банкротства. Самый сильный источник связей: устойчивая пара истец-ответчик
вскрывает хозяйственную связь, которой нет ни в одном реестре.

- `GET /` — обязательный прогрев, без сессионной куки API не отвечает
- `POST /Kad/SearchInstances`, тело:
  `{"Page":1,"Count":25,"Courts":[],"DateFrom":null,"DateTo":null,`
  `"Sides":[{"Name":"<ИНН или название>","Type":-1,"ExactMatch":false}],`
  `"Judges":[],"CaseNumbers":[],"WithVKSInstances":false}`
- заголовки: `Content-Type: application/json`, `x-date-format: iso`,
  `X-Requested-With: XMLHttpRequest`, `Referer: https://kad.arbitr.ru/`,
  браузерный `User-Agent`
- `Type` стороны: `-1` любая, `1` истец, `2` ответчик, `3` третье лицо
- ответ: `Result.Items[]`, карточка дела — `https://kad.arbitr.ru/Card/<CaseId>`

Стороны приходят в двух форматах: либо раздельными списками `Plaintiffs` /
`Respondents` / `Others`, либо одним `Sides` с числовым `Type`. Парсер
обрабатывает оба.

**Блокировка по IP.** Сервис банит адреса по частоте запросов и отдаёт HTTP 451
с HTML-страницей «Доступ заблокирован» вместо JSON. Сообщение на странице:
доступ ограничен «в связи с большим количеством запросов, направленных с вашего
адреса», контакт для разблокировки — support_kad@pravo.tech. Под бан попадают
адреса дата-центров, VPN и общие выходные узлы целиком, независимо от того,
сколько запросов сделали лично вы, и реальный браузер с такого адреса
блокируется так же, как скрипт. Работать нужно с обычного домашнего или
офисного подключения.

То же ограничение действует на `ras.arbitr.ru` (банк решений) и на
`fedresurs.ru` с `bankrot.fedresurs.ru` — последние отвечают 403 с тех же
адресов.

### Открытые данные ФНС — nalog.gov.ru/opendata
Реализовано в `scripts/opendata.py`. Массовые выгрузки на всю страну, качаются
один раз и дальше работают офлайн без лимитов.

Схема одинаковая для всех наборов: страница
`https://www.nalog.gov.ru/opendata/7707329152-<код>/` содержит ссылку на
`https://file.nalog.ru/opendata/7707329152-<код>/data-<дата>-structure-<дата>.zip`.
Внутри ZIP — тысячи XML-шардов, в каждом элементы `Документ` с атрибутами
`ДатаДок` и `ДатаСост`, вложенный `СведНП` с `ИННЮЛ` и `НаимОрг`, и набор
специфичных для набора элементов.

| Код | Что внутри | Размер | Ключевые поля |
|---|---|---|---|
| `sshr2019` | среднесписочная численность работников | 94 МБ | `СведССЧР@КолРаб` |
| `debtam` | недоимка, пени, штрафы | 71 МБ | `СведНедоим@НаимНалог @СумНедНалог @СумПени @СумШтраф` |
| `revexp` | доходы и расходы по отчётности | 100 МБ | `СведДохРасх@СумДоход @СумРасход` |
| `snr` | спецрежимы | 61 МБ | `СведСНР@ПризнЕСХН @ПризнУСН @ПризнАУСН @ПризнСРП` |

Покрытие численности: около 2,04 млн юрлиц при более чем 3 млн действующих,
одна дата (данные за 2025 год, публикация 25.07.2026). Организации под
санкциями исключены — проверено: Сбербанк, Газпром, Роснефть отсутствуют,
Магнит и МТС присутствуют. Исторических файлов на странице набора нет.

Численность относится к юрлицу, а не к группе: у ПАО «Магнит» в наборе 36
человек, потому что розница работает в дочерних юрлицах.

Ещё два набора на той же странице описывают массовость напрямую —
`massleaders` (физлица, руководящие несколькими юрлицами) и `massfounders`
(учредители нескольких юрлиц), формат CSV. Не подключены: ФНС остановила их
обновление, последняя публикация 22.05.2021 с пометкой «набор данных не
подлежит дальнейшему обновлению». Как исторический срез годятся, как текущий
признак — нет.

### Реестр деклараций СОУТ — declaration.rostrud.gov.ru
Реализовано в `scripts/rostrud.py`. Антибота нет, авторизации нет, обычный
HTML с таблицей.

`GET /declaration/index?DeclarationSearch[inn]=<ИНН>&DeclarationSearch[region_id]=&DeclarationSearch[tele]=&DeclarationSearch[verify]=0`
плюс `&page=N` для пагинации, по 20 строк на страницу.

Колонки таблицы по порядку: номер, дата внесения в реестр, полное
наименование, **место нахождения и место фактического осуществления
деятельности**, ИНН, ОГРН, индивидуальные номера рабочих мест, **профессии и
должности**, **численность работников**, организация, проводившая СОУТ,
реквизиты заключения эксперта, срок действия декларации, дата прекращения.

Номера рабочих мест, должности и численность — три параллельных списка через
запятую одинаковой длины; при расхождении длин численность лучше отбрасывать,
чем разносить наугад. В ячейке адреса нередко перечислено несколько адресов
через перенос строки.

Чем ценен: это единственный бесплатный источник, где видно **фактическое**
место работы (юридический адрес из ЕГРЮЛ с ним часто не совпадает) и состав
должностей. Первое вскрывает группы, сидящие в одном офисе под разными
юрлицами; второе показывает, держит ли компания свой рабочий персонал или
отдала работы подрядчику.

ФИО не публикуются — только должности.

### ГИС ЖКХ — dom.gosuslugi.ru
Реализовано в `scripts/gis_zhkh.py`. Публичный REST, POST + JSON, без ключа и
капчи, с адреса дата-центра работает. Формы запросов установлены по ответам
сервера: на неизвестное поле он возвращает 400 со списком допустимых полей
(`known properties: ...`).

| Что | Запрос |
|---|---|
| лицензии региона | `POST /rls/api/rest/services/license/public/search` `{"regionCode":"26","pageIndex":1,"elementsPerPage":100}` |
| лицензия по номеру | то же, `{"licenseNumber":"<номер лицензии>",...}` |
| лицензии, покрывавшие дом | то же, `{"address":{"houseGuid":"<ФИАС guid дома>"},...}` |
| дома лицензии | `POST /rls/api/rest/services/license/public/house/search` `{"licenseGuid":"…","houseStatuses":["INCLUDED"],...}` |
| карточка организации | `POST /ppa/api/rest/services/ppa/public/organizations/searchByOrg?pageIndex=1&elementsPerPage=10` `{"inn":"…"}` |

Статусы домов в лицензии: `INCLUDED`, `EXCLUDED` (с `exclusionDate`),
`CANCELED`. Статусы лицензии: `ACTIVE` и др. В записи лицензии — `licensee`
с ИНН, ОГРН, телефоном и e-mail, `houseCount`, номер ЕРУЛ.

Подвохи:

- `pageIndex` и `elementsPerPage` передаются **в теле**, а не в строке запроса —
  иначе 400.
- guid из `searchByOrg` — это не `licenseeOrgRootGuid` лицензии; по нему
  лицензии не находятся. Надёжные пути — выгрузка лицензий региона с фильтром по
  ИНН или поиск по номеру лицензии из ЕГРЮЛ.
- Телефон в карточке организации и в лицензии бывают разными (городской и
  мобильный) — брать оба.

Там же по каталогу «Реестра реестров»: реестр дисквалифицированных
руководителей УК и квалификационные аттестаты руководителей. Их эндпоинты пока
не разведаны.

### Реестр дисквалифицированных лиц ФНС
Реализовано в `opendata.py disq`. CSV,
`https://www.nalog.gov.ru/opendata/7707329152-registerdisqualified/`, около 8,4
тыс. записей, обновляется еженедельно. Имя файла содержит дату в формате
ГГГГММДД. **Описание структуры называет столбцы GA, GB, G1…G12, а в данных
заголовок G1…G14** — поля те же, номера сдвинуты, поэтому разбор по позиции.
Личного ИНН нет, только ФИО, дата и место рождения, организация с ИНН,
должность, статья КоАП, срок. В датах встречаются опечатки вида `2202` вместо
`2022`.

### Реестр реестров — reestr-reestrov.ru
Каталог 158 госреестров с паспортом каждого. Паспорта 147 реестров открыты
файлом `registries.json` под CC BY 4.0 (ссылка на источник обязательна:
«Реестр реестров, ООО «Стадика»»). Подробные карточки читаются на сайте,
расширенные данные — по договору. Полезен как карта: где что лежит, открыто
ли, есть ли выгрузка.

### ЕРКНМ — proverki.gov.ru
Реализовано в `scripts/erknm.py`. Единый реестр контрольных (надзорных)
мероприятий Генпрокуратуры: проверки, предостережения, профилактические визиты.
Для УК ЖКХ профильнейший источник.

**Поиск на сайте защищён капчей** — при отправке формы фронтенд запрашивает
`GET /public/api/captcha`, а `/public/api/inspections/search` без токена
отвечает 400 с пустым телом на любые параметры. Этот путь закрыт и обходить его
не нужно: у реестра есть официальный машиночитаемый экспорт.

Открытые данные, капчи нет:

- `GET /public/api/opendata/list?isFederalLaw248=true` → `{years, months,
  registryXmlUrl}`. Флаг `isFederalLaw248` переключает ЕРКНМ (248-ФЗ, с 2021)
  и старый ЕРП (294/131/184-ФЗ)
- `GET /public/api/opendata/{год}/{месяц}?isFederalLaw248=true` → паспорт
  набора, в нём `dataZipUrl`, `structureXsdUrl` и вся история публикаций
- сам архив: `https://proverki.gov.ru//blob/erknm-opendata/{год}/{месяц}/data-<дата>-structure-<дата>.zip`

Внутри ZIP один XML на месяц, около 300 МБ в распакованном виде. Сервер рвёт
соединение на таких объёмах — качать только с докачкой через `Range`.

Структура XML не соответствует XSD по способу хранения: **всё лежит в
атрибутах**, а не в тексте элементов, и объявлен namespace
`https://proverki.gov.ru/opendata/3.0/20220115`, поэтому теги приходят как
`{ns}INSPECTION`. Значимые поля:

| Где | Что |
|---|---|
| `INSPECTION/@ERPID` | номер мероприятия |
| `INSPECTION/@STATUS`, `@TYPE_NAME` | статус, плановое/внеплановое |
| `INSPECTION/@START_DATE`, `@STOP_DATE`, `@DURATION_DAYS` | сроки |
| `SUBJECT/@INN`, `@OGRN`, `@NAME`, `@MSP_CODE` | проверяемое лицо |
| `KND_KNM/@VALUE`, `KIND_CONTROL/@VALUE` | вид мероприятия и вид контроля |
| `KNO_ORGANIZATION/@VALUE` | орган контроля |
| `PROSECUTOR_OFFICE/@NAME` | орган прокуратуры |
| `OBJECT/@ADDRESS`, `RISK_CATEGORY/@VALUE` | объект и категория риска |
| `INSPECTOR/@INSPECTOR_FULL_NAME` | ФИО инспектора |

Условия использования: свободно и бесплатно, в том числе для создания программ,
с обязательным сохранением ссылки на источник.

## Не подключено, но доступно бесплатно

### Госзакупки — zakupki.gov.ru
44-ФЗ и 223-ФЗ, официальный открытый доступ. Совместные участия и совпадающие
контактные лица в заявках — рабочий признак аффилированности.

Практическая деталь: сайт использует сертификат российского УЦ, поэтому
`curl` падает с `SSL certificate problem: unable to get local issuer certificate`.
Нужно поставить корневой сертификат Минцифры в системное хранилище.

### Прочие наборы открытых данных ФНС
На той же странице лежат ещё несколько наборов по юрлицам, которые в скил не
заведены, но берутся тем же кодом из `opendata.py` — достаточно добавить запись
в `DATASETS`: `taxoffence` налоговые правонарушения и меры ответственности,
`kgn` участие в консолидированной группе налогоплательщиков, `rsmp` единый
реестр субъектов МСП, `registerdisqualified` реестр дисквалифицированных лиц.

Полный дамп ЕГРЮЛ у ФНС платный (порядка 150 тыс. руб/год), перечисленные
наборы бесплатны.

### Федресурс — fedresurs.ru
Залоги, лизинг, сообщения о реорганизации, банкротные сообщения, намерения
кредиторов. Есть JSON-эндпоинты `fedresurs.ru/backend/companies` и
`bankrot.fedresurs.ru/backend/companies` с параметром `searchString`, но с
адресов дата-центров они отвечают 403 — та же история, что с kad.arbitr.ru.

### ФССП
Исполнительные производства. Официальный API `api.fssp.gov.ru` требует токен,
выдаётся по заявке.

### Реестр залогов движимого имущества — reestr-zalogov.ru
Заложенные доли в ООО. Прямо показывает, кто реально контролирует компанию,
когда номинальный владелец — не бенефициар.

### b2b.house — проверено, в скил не годится
Агрегатор ООО «Промтех». Карточка компании богатая: финансы, численность по
годам, проверки ЕРКНМ, арбитраж, исполнительные производства, закупки, РНП,
лицензии, товарные знаки, связи, учредители. Подстраницы:
`/company/<slug>_<uuid>/{financial-statements,arbitration-cases,inspections,
executive-productions,purchases,licenses,trademarks,dishonest-suppliers}/`.

Антибот обходится: первый GET отдаёт 65 байт с
`<script>!navigator.webdriver && window.location.reload()</script>` и ставит
куки, повторный GET с теми же куками отдаёт полную страницу.

**Блокирующая проблема — нет резолва ИНН в URL.** Публичный поиск не работает
ни по ИНН, ни по названию: и `/search/?q=...`, и ввод в поисковую строку живого
браузера возвращают один и тот же дефолтный список (Ростелеком, Сфера,
Альбатрос). Карта сайта — 965 частей по 10 МБ, около 48 млн URL, ИНН в ней нет,
только `slug_uuid`. Без аккаунта перейти от ИНН к странице нечем, поэтому
автоматизировать нельзя.

Сверка данных: финансы совпали с ГИР БО до рубля (выручка 184 384 000 ₽,
чистая прибыль 33 162 000 ₽ у одной и той же компании), то есть источник тот
же и нового не даёт. Уникальны только два раздела — проверки ЕРКНМ и
численность за несколько лет.

Вывод: как ручной инструмент, когда URL уже есть на руках, — полезен. Как
источник для скила — нет.

## Платные агрегаторы

Нужны, только если требуется обратный поиск «человек → все его компании» или
готовый граф аффилированности.

| Сервис | Чем полезен | Порядок цены |
|---|---|---|
| Checko API v2.4 | 13 эндпоинтов: компании, ИП, физлица, финансы, суды, закупки, приставы, Федресурс, банкротства, история изменений | тысячи руб/мес |
| Rusprofile | **используется** в `people.py`: страница человека по шаблону `/person/<фамилия>-<инициалы>-<ИНН>`, без поиска и без лимита. Отдаёт список компаний с ИНН, выручкой, адресом и историю выходов из состава с датами. Финансовые детали в карточке компании замаскированы | часть данных бесплатно |

## Признаки, которые стоит проверять

Связи:
- один директор или учредитель в нескольких компаниях — самый твёрдый признак
- совпадение адреса регистрации, особенно неmassовый адрес
- цепочка владения через промежуточные ООО с номинальным капиталом
- управляющая организация вместо директора
- совпадение телефонов и email в закупочной документации
- регулярные встречные иски или, наоборот, полное отсутствие споров при
  крупных взаимных оборотах

Финансовые:
- отрицательный капитал — техническая несостоятельность
- выручка в десятки раз больше активов — возможен транзит
- уставный капитал 10 тыс. руб при миллиардной выручке
- резкий обвал выручки перед сменой владельца
- нулевая выручка при поданной отчётности
- отсутствие отчётности за последний год у действующей компании

Регистрационные:
- смена директора или адреса незадолго до сделки
- статус реорганизации или ликвидации
- недостоверность сведений в ЕГРЮЛ — прямая отметка в выписке
- возраст компании меньше года при крупном контракте
